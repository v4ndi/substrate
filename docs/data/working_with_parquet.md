# Работа с parquet-файлами

Низкоуровневые примитивы чтения parquet живут в `avatar.data.base.parquet`.
Наиболее ходовые из них — `parquet_num_rows` и `read_parquet_file` —
реэкспортированы из `avatar.data`, поэтому в прикладном коде обычно достаточно
`from avatar.data import parquet_num_rows`.

Это фундамент, на котором построены датасеты (`avatar.data.base.iterable`):
сами вы будете вызывать эти функции только при разведке данных или при написании
собственного датасета. Как читают данные готовые датасеты, описано в
[руководстве по датасетам](../guides/datasets.md).

## Общее свойство: параметр `filesystem`

Все четыре функции принимают необязательный `filesystem` —
`pyarrow.fs.FileSystem`, на котором лежит путь. Если передан `None`, pyarrow
разрешает путь сам, то есть работает с локальным диском. Именно так эти функции
вели себя до появления поддержки HDFS, поэтому локальный код менять не пришлось.

Получить файловую систему по URI или по конфигу можно через
`avatar.data.resolve_filesystem`.

## Функции

### `parquet_num_rows(path, filesystem=None) -> int`

Количество строк в **одном** parquet-файле, прочитанное из футера с
метаинформацией — данные при этом не читаются, поэтому вызов практически
бесплатный.

```python
>>> from avatar.data import parquet_num_rows
>>> parquet_num_rows("data/part-0.parquet")
1011
```

Функция работает по одному файлу, а не по директории: чтобы посчитать строки в
партиционированном датасете, сложите значения по всем его файлам. Планировщик
шардирования (`avatar.data.ShardPlanner`) делает именно это.

### `read_parquet_file(file, columns=None, shuffle=True, filesystem=None)`

Генератор по строкам файла. Каждая строка — словарь `{имя колонки: numpy-массив}`.

```python
>>> from avatar.data import read_parquet_file
>>> for record in read_parquet_file("data/part-0.parquet", columns=["id", "value"]):
...     print(record["id"].item(), record["value"].item())
```

О чём стоит помнить:

* Скалярные значения тоже приходят numpy-массивами — для получения питоновского
  числа используйте `.item()`.
* При `shuffle=True` файл целиком загружается в память, чтобы перемешать строки.
  Для больших файлов передавайте `shuffle=False` либо ограничивайте `columns`.
* `columns=None` читает все колонки; явный список ощутимо ускоряет чтение.

### `read_parquet_columns(path, columns, filesystem=None) -> pyarrow.Table`

Читает подмножество колонок одного файла целиком в `pyarrow.Table`. Используется
фазой сканирования датасета: там нужны только те колонки, которые читает фильтр
или счётчик длин, но никогда — полезная нагрузка.

### `open_parquet_file(path, filesystem=None)`

Контекстный менеджер, отдающий `pyarrow.parquet.ParquetFile`. Нужен, когда
требуется добраться до метаданных или row group напрямую; остальные три функции
построены на нём.

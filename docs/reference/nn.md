# Справочник: `fmlib.nn`

Каталог строительных блоков. Как они складываются в модель — в
[../guides/models.md](../guides/models.md).

Главное свойство всего пакета: **ни один блок здесь не считает функцию потерь**.
Она принадлежит пайплайну ([reference/pipeline.md](pipeline.md)). Благодаря
этому один и тот же энкодер работает и в классификации, и в uplift, и на
инференсе, где таргетов нет вовсе.

## Что с чем сочетается

```
табличный стек:
  TabularEmbedding ──► TabularTransformer ──► агрегация ──► пайплайн
  (B, F)               (B, F, D)              (B, F, D)      (B, D)

последовательностный стек:
  EventSequenceEmbedding ──► EventEncoder ──► backbone ──► агрегация
  событие                    (B, S, H)        (B, S, H)     (B, H)
```

Совместимость определяется формой, а не наследованием: энкодер принимает
эмбеддинги, а не батч, поэтому эмбеддинг можно менять независимо.

## Эмбеддинги — `fmlib.nn.embedding`

### Табличные

| класс | что делает |
|---|---|
| `TabularEmbedding` | батч → `(B, F, D)`, по токену на признак |
| `NumericFeatureEmbedding` | эмбеддинг стандартизованных числовых колонок |
| `BaseTabularEmbedding` | базовый класс для своих реализаций |

Все категориальные колонки делят **одну** таблицу эмбеддингов, индексируемую
идентификаторами со сквозной нумерацией, которые выдаёт препроцессор. Поэтому
`vocab_size` — одно число, а не по числу на колонку.

Обе группы признаков необязательны: `num_numerical_features=None` для чисто
категориальной таблицы, `vocab_size=None` — для чисто числовой.

### Подмешивание внешнего эмбеддинга (early fusion)

| класс | эффект | +1 токен |
|---|---|---|
| `LayerNormConcatenate` | добавляет внешний вектор как отдельный токен | да |
| `LayerNormSum` | прибавляет его ко всем токенам | нет |
| `BaseHiddenStateAggregator` | базовый класс | — |

`LayerNormConcatenate` увеличивает число токенов, поэтому `num_features` в
`aggregation_config` должен быть на единицу больше. Это самая частая ошибка в
конфигах с внешними эмбеддингами.

### Последовательностные

| класс | что делает |
|---|---|
| `EventSequenceEmbedding` | эмбеддинг атрибутов одного события |
| `TemporalPositionEncoding` | классическое синусоидальное кодирование позиции |
| `Time2VecEmbedding` | обучаемое периодическое представление самой временной метки |
| `BaseEventSequenceEmbedding`, `BaseTemporalEmbedding` | базовые классы |

`Time2Vec` кодирует **время**, а не позицию, поэтому неравномерные промежутки
между событиями остаются значимыми. Для транзакционных данных это обычно
уместнее позиционного кодирования.

### Общие примитивы

| класс | что делает |
|---|---|
| `LinearEmbeddings` | каждому числовому признаку — своя проекция |
| `HashEmbedding` | хеш-таблица фиксированного размера для колонок с огромной мощностью |
| `BaseEmbedding` | корень иерархии |

`HashEmbedding` меняет коллизии на ограниченный размер таблицы — вариант для
идентификаторо-подобных колонок, которым словарь не построить.

## Табличные энкодеры — `fmlib.nn.tabular`

| класс | что делает |
|---|---|
| `TabularTransformer` | self-attention по токенам-признакам, `(B, F, D) -> (B, F, D)` |
| `BaseTabularEncoder` | базовый класс; от него наследуйте свой энкодер |
| `EncoderBlock`, `SublayerConnection` | блоки трансформера |
| `build_feature_padding_mask` | маска паддинга по токенам-признакам |

`TabularTransformer` — это attention **по признакам**, а не по объектам:
последовательность для него — это набор признаков одной записи.

## Последовательностные модели — `fmlib.nn.sequential`

| класс | что делает |
|---|---|
| `EventEncoder` | кодирует одно событие: внимание по его атрибутам, затем пулинг |
| `IntraFeatureAttention` | то самое внимание внутри события |
| `EventAggregator` | сворачивает атрибуты события в один вектор |
| `TransformersWrapper` | адаптер под backbone из HuggingFace `transformers` |
| `SequenceBackbone` | протокол backbone: `(B, S, H) -> (B, S, H)` |
| `BaseBackbone`, `BaseSequenceModel`, `BaseEventEncoder` | базовые классы |
| `build_event_attention_mask` | маска по атрибутам события |

`SequenceBackbone` — это `Protocol`, а не базовый класс: модель из
`transformers` удовлетворяет ему, ничего не наследуя.

Двухуровневая структура (внимание внутри события, затем внимание между
событиями) — это то, что позволяет одной последовательности нести события
разных типов с разным набором атрибутов.

## Агрегация — `fmlib.nn.utils`

`get_aggregation_layer(name, **kwargs)` выбирает слой по имени; это то, во что
разрешается блок `aggregation_config`.

| имя | класс | нужны аргументы |
|---|---|---|
| `mean` | `MeanHiddenState` | — |
| `sum` | `Sum` | — |
| `sum_layernorm` | `SumLayerNorm` | `emb_dim` |
| `last` | `LastHiddenState` | — |
| `linear` | `LinearAggregation` | `num_features`, `emb_dim` |
| `conv` | `ConvAggregation` | `emb_dim`, `kernel_size` |

`linear` и `conv` требуют фиксированного числа токенов, поэтому применимы к
табличным данным, но не к последовательностям переменной длины. `mean`, `sum` и
`last` учитывают маску внимания.

`BaseAggregation` — базовый класс; его `layer_idx` меньше −1 означает
агрегацию не по последнему слою, и модель тогда автоматически переключается на
возврат всех скрытых состояний.

Там же `FeedForwardNetwork` — настраиваемый feed-forward блок, из которого
собраны все головы. Порядок dropout, активации и нормализации в нём
настраивается, потому что головы в этом репозитории используют оба варианта.

## Как добавить свой блок

Наследуйтесь от подходящего базового класса, соблюдайте форму входа и выхода и
**не считайте потери**:

* табличный энкодер — `BaseTabularEncoder`, вход `(B, F, D)`, выход
  `BaseTabularOutput`;
* агрегация — `BaseAggregation`;
* эмбеддинг — `BaseTabularEmbedding` или `BaseEventSequenceEmbedding`;
* временное кодирование — `BaseTemporalEmbedding`.

Регистрировать ничего не нужно: в конфиге это обычный `_target_`.

# Ревью модуля `avatar.metrics`

Ревизия: `598799e` (`refactor/data-sharding-hdfs` после мерджа PR #4 и #6).
Объём модуля: 3024 строки, 25 публичных классов, 13 файлов.

Всё, что помечено **[подтверждено]**, воспроизведено запуском кода на этой ревизии,
а не выведено чтением. Всё остальное — вывод из чтения, помечено **[по коду]**.

Проверить подтверждённое одной командой: `python metrics_review_repro.py` из корня
репозитория. Машинная часть анализа мёртвого кода — в `metrics_review_deadcode.txt`.

---

## 1. Резюме

Модуль устроен правильно по крупному счёту: контракт `update` / `compute` / `reset`
описан в `docs/guides/metrics.md`, отделены считающие числа метрики от сборщиков
файлов и от бенчмарков, композиция через обёртки работает, а новый цикл
`avatar/train/evaluate.py` корректно решил самую тяжёлую задачу — неаддитивные метрики
(ROC AUC, qini) считаются по всей популяции на ранге 0, а не по шардам с усреднением.
Это ровно тот выбор, который надо было сделать, и он задокументирован.

Проблема в другом: **между контрактом, докстрингами и кодом накопился разрыв**.
Модуль почти не покрыт тестами — на 3024 строки приходится один файл
`tests/metrics/test_seq_stats.py`, — и без тестов расхождения копились молча.
Ниже 3 дефекта, ломающих прогон, и 12, тихо портящих числа. Половина из них
воспроизводится в три строки.

Второй вывод: **ровно половина модуля никем не используется** — 12 классов из 25,
1507 строк из 3024, не встречаются ни в одном рабочем конфиге, ни в коде, ни в тестах.

Оценка по частям:

| Часть | Состояние |
|---|---|
| Контракт `BaseMetric` и его место в трейне | хорошо, но не типизирован по видам метрик |
| `avatar/train/evaluate.py` (сведение по рангам) | правильная схема, дорогая реализация |
| `RocAucScore`, `GroupAverage/GroupDevided` | рабочие, есть краевые дефекты |
| `UpliftMetrics` | работает, но методологически некорректная калибровка + `assert` в проде |
| `avatar/metrics/supervised.py` | самая слабая часть: 2 из 5 классов мертвы, в живых — схлопывание ключей |
| `avatar/metrics/campaign.py` | сборщики рабочие; 3 из 6 классов мертвы |
| `avatar/metrics/moe_reg.py`, `avatar/metrics/loss_logging.py`, `avatar/metrics/multi_loss.py` | маленькие, и все три считают не то, что написано в докстринге |
| Тесты | практически отсутствуют |

## 2. Что сделано хорошо

Отмечаю, чтобы при правках это не потерялось.

* **Выбор режима сведения по признаку шардирования датасета**
  (`avatar/train/evaluate.py`, `dataloader_is_sharded`). Реплицированный датасет не
  собирается — иначе каждая запись попала бы в метрику `world_size` раз. Форвард при
  этом выполняют все ранги, чтобы никто не завис на коллективе. Это тонкое место, и
  оно сделано верно.
* **`compute` только на ранге 0 и рассылка решений оттуда же.** Альтернатива —
  сводить «хотя бы один ранг сказал стоп» — привела бы к рассинхрону чекпоинтов.
* **`GroupDevidedMetricsWrapper` требует `_partial_: true`** и это объяснено в
  докстринге: без фабрики все группы делили бы один накопитель. Ровно та ошибка,
  которую легко сделать и невозможно заметить по логам.
* **`UniversalLossesMetric` находит поля рефлексией**, а не по списку имён: новая
  вспомогательная функция потерь начинает логироваться без правки конфига.
* **Документация модуля** (`docs/guides/metrics.md`, `docs/reference/metrics.md`)
  заметно выше среднего по репозиторию — описан и контракт, и режимы сведения, и
  композиция.

## 3. Дефекты, ломающие прогон

### B1. Четыре сборщика возвращают `None` из `compute()` — новый трейн падает на этом

**[подтверждено]**

Цикл делает `scores.update(metric.compute())`:

* `avatar/train/evaluate.py:101` — валидация,
* `avatar/train/evaluate.py:150` — инференс,
* `avatar/train/callbacks/metrics.py:54` — train-метрики.

А `compute()` не возвращает ничего у четырёх классов:

| Класс | Где | Ссылок в конфигах |
|---|---|---|
| `ClassificationInferenceMetrics` | `avatar/metrics/base.py:187` | 4 |
| `InferenceMultiTaskCampaignMetrics` | `avatar/metrics/campaign.py:445` | **23** |
| `InferenceMultiTaskResponseMetrics` | `avatar/metrics/campaign.py:552` | 0 |
| `InferenceSupervisedMetrics` | `avatar/metrics/supervised.py:541` | 0 |

`{}.update(None)` → `TypeError: 'NoneType' object is not iterable`.

Это **регрессия рефакторинга**: в базовой ревизии `7c96504` инференс делал
`scores = metrics.compute()` (`avatar/inference.py:75`) и спокойно жил с `None`.
Новый `predict()` превратил это в падение — в самом конце прогона, уже после того,
как parquet записан. Данные не теряются, но задача завершается с ненулевым кодом.

Соседний `CollectEmbeddings.compute` (`avatar/metrics/campaign.py:166`) возвращает
`{}` и работает — то есть правильный ответ в модуле уже есть, просто не везде.

**Фикс:** `return {}` в четырёх местах. Минута работы. Но настоящая причина — в
разделе 6 (контракт).

### B2. `assert` внутри метрики убивает обучение

**[подтверждено на практике]** — это ровно то, обо что споткнулась кампания сравнения
обучений в прошлой задаче.

`avatar/metrics/uplift.py:83-91`:

```python
assert abs(calib_c_roc_auc - c_roc_auc) < 0.01
assert abs(calib_t_roc_auc - t_roc_auc) < 0.01
```

Проверка сама по себе разумная: бета-калибровка монотонна и не должна менять
ранжирование. Но недообученная модель выдаёт почти константные скоры, ROC AUC на них
шумит сильнее 0.01 — и **валидация роняет весь прогон обучения**. Метрика не должна
иметь права остановить обучение: её задача — сообщить число.

**Фикс:** превратить в метрику. Вместо `assert` писать
`calibration_rank_shift = abs(calib_roc_auc - roc_auc)` в результат и логировать
`warnings.warn` при превышении порога. Тогда проблема видна в MLflow, а прогон живёт.

### B3. `RegressionMetrics` схлопывает все метрики в один ключ

**[подтверждено]** `avatar/metrics/supervised.py:433`:

```python
f"{task_name}_" if len(task_name) != 0 else "" + key: val
```

Приоритет операторов разбирает это как `(f"{task_name}_") if cond else ("" + key)`.
При непустом `task_name` ключом становится `"prod_a_"` — **без имени метрики**. Все
три метрики пишутся в один ключ, выживает последняя:

```
{'mse': 1.0, 'mae': 2.0, 'mape': 3.0}  ->  {'prod_a_': 3.0}
```

При пустом `task_name` (одна задача) ветка другая и всё корректно, поэтому дефект
виден только в многозадачном режиме. Правильный вариант — как в соседних классах:

```python
f"task_{task_name}_{key}" if len(str(task_name)) != 0 else key
```

## 4. Дефекты, тихо портящие числа

### S1. `Entropy` возвращает энтропию с обратным знаком

**[подтверждено]** `avatar/metrics/moe_reg.py:35` считает `sum(p·log p) / log(n)`, тогда
как нормированная энтропия — это `−sum(p·log p) / log(n)`.

```
равномерное распределение по 4 экспертам -> -1.0    (докстринг обещает ~1)
коллапс на одного эксперта               -> -6e-11  (докстринг обещает ~0)
```

Метрика работает как индикатор (монотонна), но знак и интервал не те, что написаны, и
дашборд с «энтропией −1 = здорово» читается наоборот. Соседний `ExpertsWorkload`
(`avatar/metrics/sequence_stats.py:120`) берёт минус правильно — то есть в модуле две
разные реализации одной величины с разным знаком.

### S2. `MultiLossMetric`: среднее отношений вместо отношения сумм, и `compute` не идемпотентен

**[подтверждено]** Три дефекта в 20 строках (`avatar/metrics/multi_loss.py`):

1. Считается `mean(loss_i / n_i)` вместо `sum(loss_i) / sum(n_i)`. На батчах
   `(loss=2, n=4)` и `(loss=4, n=2)` получается **1.25** вместо корректных **1.0**.
   Ровно то смещение, которое докстринг обещает устранить («heads with different
   numbers of valid targets stay comparable»).
2. `compute()` мутирует `self.losses`, подменяя список числом. Второй вызов даёт
   **0.46875** — мусор. Контракт в `base.py:64` явно требует «Should not modify
   internal state».
3. `if self.num_items[attribute] != 0` (строка 40) сравнивает **список** с нулём —
   всегда истина, ветка `else` недостижима.

### S3. `UniversalLossesMetric` делит на глобальный счётчик батчей

**[подтверждено]** `avatar/metrics/loss_logging.py:33-36`. Докстринг обещает:
«a loss that only applies to some batches is averaged over the batches where it
exists». Код использует общий `self.update_counter`, а не счётчик по полю. Потеря,
присутствующая в 1 батче из 4 и всегда равная 1.0, логируется как **0.25**.

Плюс среднее по батчам не взвешено размером батча: последний неполный батч имеет тот
же вес, что и полный.

### S4. `RocAucScore` возвращает `nan`, и один `nan` навсегда выключает раннюю остановку

**[подтверждено]** `avatar/metrics/classification.py:82-86`. Защита асимметрична:
`sum(targets) > 0` ловит срез без единого позитива (возвращается 0.5), но не ловит срез
**из одних позитивов** — там `sklearn` предупреждает и возвращает `nan`.

Дальше `nan` попадает в `EarlyStopping` (`avatar/train/early_stopping.py:85`):

```python
elif score < self.best_score + self.delta:   # nan < nan  ->  False
```

Сравнение с `nan` всегда ложно, поэтому исполняется ветка «улучшение»:
`best_score = nan`, счётчик обнуляется. После этого **любой** следующий скор тоже даёт
`False` — ранняя остановка не сработает уже никогда, а `best_metric` в состоянии
тренера останется `nan`.

**Фикс** в двух местах: проверять `len(set(targets)) > 1`, а не сумму; и научить
`EarlyStopping` пропускать нечисловой скор вместо того, чтобы принимать его за рекорд.

### S5. `GroupAverageMetricWrapper` фиксирует regex-группы на первом `compute`

**[подтверждено]** `avatar/metrics/utils/group_average_wrap.py:48-60`. Список имён,
подпадающих под регулярное выражение, вычисляется один раз и переиспользуется.
А `GroupDevidedMetricsWrapper` создаёт группы **лениво, по мере появления в данных**.
Если на первой эпохе валидации встретилась одна группа, а на второй — две:

```
эпоха 1 -> {'g_0_auc': 1.0, 'avg_auc': 1.0}
эпоха 2 -> {'g_0_auc': 1.0, 'g_1_auc': 0.0, 'avg_auc': 1.0}   # g_1 не вошёл в среднее
```

Среднее по определению не полное, и это не видно в логах. Обёртка используется в
21 конфиге — самая популярная в модуле.

**Фикс:** пересчитывать группы на каждом `compute` (это дешёвый `re.search` по десяткам
имён), а не кэшировать.

### S6. `UpliftMetrics`: калибратор обучается и проверяется на одних и тех же строках

**[по коду]** `avatar/metrics/uplift.py:219-222`. Если в батче нет колонки `split_type`
— а её нет во всех конфигах пилота, — весь срез помечается как `"calib"`. Тогда:

* `test_group_mask` пуст, `test_scores` пуст;
* калибратор фитится на `calib_group_mask` (строки 241-249) и на нём же оценивается
  (строки 262-272);
* в `mean_{main_metric}` уходит **in-sample** число (строки 317-326).

То есть в конфигурации по умолчанию главная метрика прогона оптимистически смещена.
Проверка `is_calib=True` (строки 85-91) при этом всегда проходит именно потому, что
данные те же — она проверяет не качество, а тождество.

**Фикс:** без `split_type` либо не выдавать калиброванные метрики вовсе, либо считать
их cross-fitting'ом (обучить калибратор на K−1 фолдах, применить к отложенному). Второе
честно и стоит одного лишнего прохода по массиву.

### S7. `require_calibration: False` не отключает калибровку

**[подтверждено на практике]** Флаг влияет только на то, какая метрика попадает в
`mean_*` (`avatar/metrics/uplift.py:306-326`). Калибраторы фитятся всегда, ассерты из
B2 выполняются всегда, калиброванные метрики считаются всегда. Пользователь, который
выключил флаг, чтобы обойти падение из B2, обнаружит, что оно осталось. Имя параметра
обещает не то, что он делает.

### S8. При `require_calibration: True` две разные метрики получают одно значение

**[по коду]** `avatar/metrics/uplift.py:346-348`: `mean_calibrated_X` и `mean_X`
записываются из одного и того же списка. Некалиброванное среднее в этом режиме получить
невозможно, хотя ключ для него в логе есть.

### S9. Метрика молча дописывает в данные позитивный пример

**[по коду]** `avatar/metrics/uplift.py:25-26` и `48-49`:

```python
if y_true.sum() == 0:
    y_true[0] += 1
```

Мотив понятен (не ронять прогон на вырожденном срезе) и он честно описан в докстринге.
Но происходит это без единой строчки в логе, а `+= 1` вместо `= 1` на неудачных
данных даст метку `2`. Правильнее — вернуть `nan`/пропустить группу и **сказать об
этом** в предупреждении.

### S10. `PLEResponseMetrics`: ключ перезаписывается в цикле

**[по коду]** `avatar/metrics/supervised.py:830-835`. В глобальной ветке
`result[f"{prefix}_any_specific_expert_mean"]` пишется внутри цикла по
`specific_idx`, а значение зависит от `actual_idx`. Все итерации, кроме последней,
выброшены; итоговое число — сумма по хвосту от последнего индекса, а не «утилизация
специфичных экспертов». Вычисление надо вынести из цикла с `actual_idx =
num_shared_experts`. (Класс мёртв — см. раздел 7, — но если его будут оживлять, это
первое, что нужно поправить.)

### S11. `SequenceStats` делит на размер первого батча

**[по коду]** `avatar/metrics/sequence_stats.py:59-61`: знаменатель
`len(context_lengths) * self._batch_size`, где `_batch_size` запомнен с первого батча.
Последний батч почти всегда неполный, значит средняя длина контекста систематически
занижена. Считать надо по фактическому числу записей.

### S12. `GroupDevidedMetricsWrapper.reset()` не забывает группы

**[по коду]** `avatar/metrics/utils/group_devided_wrap.py:112-114` сбрасывает вложенные
метрики, но оставляет `self.group2metrics`. Группа, которая была на первой эпохе и
исчезла на второй, останется в словаре, и её пустая метрика попадёт в `compute`.
Контракт (`base.py:75`) требует «as if newly instantiated».

## 5. Устойчивость и стоимость на новом трейне

Здесь ничего не сломано, но новый трейн изменил цену этих решений.

### P1. `all_gather_object` там, где нужен `gather_object(dst=0)`

`avatar/train/dist.py:132-138` собирает объект **на все ранги**, после чего
`evaluate.py:80` отбрасывает результат везде, кроме нулевого. Трафик и пиковая память
завышены в `world_size` раз без всякой пользы. `torch.distributed.gather_object(obj,
object_gather_list if rank == 0 else None, dst=0)` даёт то же самое дешевле.

### P2. Через сеть гоняются целые батчи, включая то, что метрике не нужно

`evaluate.py:79` и `callbacks/metrics.py:39` сериализуют `(batch, output)` целиком:
все входные тензоры, все скрытые состояния, все головы. `RocAucScore` из этого читает
два поля — `inputs["targets"]` и `outputs.logits`. При record-level шардировании из
`data_redesign` это и есть главный потолок пропускной способности валидации.

Дешёвое лекарство, не требующее переписывания модуля: дать метрике декларацию нужных
полей и собирать только их.

```python
class RocAucScore(BaseMetric):
    required_inputs = ("targets",)
    required_outputs = ("logits",)
```

Дорогое и правильное — раздел 6, пункт 2.

Отдельно: `TrainMetricsCallback.on_forward_end` делает этот сбор **на каждом шаге
обучения**, а не раз в эпоху. Если train-метрики включены в distributed-прогоне, это
заметная доля времени шага.

### P3. `os.makedirs(..., exist_ok=False)` роняет второй запуск

`avatar/metrics/base.py:104` и `avatar/metrics/supervised.py:497`. Директория,
оставшаяся от предыдущего прогона, приводит к `FileExistsError` при **создании**
метрики — то есть до начала обучения. Соседние места (`campaign.py:107`,
`supervised.py:105`) используют `exist_ok=True`. Разнобой.

### P4. Имена файлов с точностью до секунды затирают друг друга

`base.py:107`, `campaign.py:58`, `campaign.py:478`, `supervised.py:106`,
`supervised.py:572` — все строят имя из `datetime.now()` с точностью до секунды.
Сборщики сбрасывают буфер каждые `save_steps` батчей; два сброса внутри одной секунды
— обычное дело на быстрых батчах, и второй parquet **молча затирает первый**. Нужен
монотонный счётчик части (`part-00001.parquet`) или добавление ранга и uuid.

### P5. `GroupDevidedMetricsWrapper` не работает на train-метриках

**[подтверждено]** `avatar/metrics/utils/group_devided_wrap.py:65` делает
`copy.deepcopy(outputs)`. На валидации это безопасно (`@torch.inference_mode()`), но на
выходе обучающего шага тензоры не листовые:

```
RuntimeError: Only Tensors created explicitly by the user (graph leaves)
support the deepcopy protocol at the moment.
```

Плюс сам по себе `deepcopy` всего выхода на каждую группу и каждый батч — это
`O(групп × размер батча)` лишних копий, тогда как нужен только `logits[ids]`.

### P6. `print` вместо логгера

`base.py:125`, `campaign.py:68`, `campaign.py:487`, `sequence_stats.py:69`,
`supervised.py:116`, `supervised.py:581`, `uplift.py:361`. В многоранговом прогоне это
перемешанный вывод без отметки ранга. `sequence_stats.py:69` печатает весь словарь
статистик на каждый `compute` — это отладочный вывод, забытый в коде.

## 6. Что предлагаю поменять (и почему именно так)

### 1. Разделить контракт на «числа» и «файлы» — это убирает B1 навсегда

Сейчас `BaseMetric.compute()` обязан возвращать `dict[str, float]`, но половина
наследников по смыслу возвращает файл. Отсюда четыре класса, забывшие `return {}`, и
падение на самом ходовом конфиге.

```python
class ScalarMetric(BaseMetric):
    def compute(self) -> dict[str, float]: ...

class ArtifactMetric(BaseMetric):
    def flush(self) -> None: ...          # пишет parquet
    def compute(self) -> dict[str, float]:
        self.flush()
        return {}                          # один раз, в базовом классе
```

Цикл `evaluate` тогда не может получить `None` в принципе — не потому, что все
наследники аккуратны, а потому, что возвращать `None` неоткуда. Дешевле, чем ловить
это ревью.

### 2. Перейти на контракт `torchmetrics` для аддитивной части

Индустриальный стандарт для PyTorch — `torchmetrics.Metric`: состояние объявляется
через `add_state(..., dist_reduce_fx="sum" | "cat")`, а синхронизация между рангами
происходит внутри `compute()`. Что это даёт здесь:

* **аддитивные метрики** (счётчики, суммы потерь, доли) сводятся `all_reduce` по
  нескольким скалярам вместо пересылки батчей — это снимает P2 для большей части
  метрик;
* **неаддитивные** (`BinaryAUROC`, и есть готовый) собирают `cat`-состояние, то есть
  гоняют по сети **только `preds` и `target`**, а не весь батч с эмбеддингами;
* исчезает целый класс дефектов S2/S3 — накопители пишутся декларативно, а не руками.

`BinaryAUROC` из коробки заменяет `RocAucScore` вместе с его DDP-логикой. Обёртки
`GroupAverage`/`GroupDevided` имеют прямые аналоги — `MetricCollection` и
`ClasswiseWrapper`.

Специфичные для задачи метрики (uplift, qini, кампанейские сборщики) на torchmetrics
не переводятся и остаются своими — но их и стоит оставить в стороне, они и есть
ценность модуля.

Реалистичный порядок: сначала пункт 1 и пункт 3, потом `RocAucScore` → `BinaryAUROC`
как пилот, дальше по факту.

### 3. Декларация нужных полей вместо пересылки всего батча

Описано в P2. Самое выгодное соотношение «эффект / объём правки» из всего списка:
две строки на метрику плюс фильтр в `avatar/train/evaluate.py` и `avatar/train/callbacks/metrics.py`.

### 4. Метрика не имеет права останавливать обучение

Убрать `assert` из `avatar/metrics/uplift.py` (B2), убрать `assert` из `sequence_stats.py:105`
(там `assert hasattr(...) is not None` — выражение всегда истинно, проверка
декоративная). Общее правило: невалидные данные → предупреждение и пропуск ключа;
исключение допустимо только на этапе конструирования метрики, до старта обучения.

### 5. Числовая гигиена на границе

* Возвращать `float(...)`, а не `np.float64` и не внутренний `defaultdict`
  (`loss_logging.py:39`, `multi_loss.py:47` отдают наружу собственное состояние —
  вызывающий может его испортить).
* Не писать `nan` в результат: пропускать ключ и предупреждать. Тогда S4 не сможет
  сломать раннюю остановку даже если проскочит.
* `EarlyStopping` должен явно игнорировать нечисловой скор.

### 6. Убрать тройное дублирование блока task/group

`UpliftMetrics.compute`, `ResponseMetrics.compute` и `RegressionMetrics.compute` — это
три копии одного ~100-строчного цикла с масками по `task_name` / `group` / `split_type`
и одинаковым хвостом сохранения submit'а. B3 живёт ровно в той копии, куда исправление
не доехало. Общий `_TaskGroupScorer`, которому передают функцию подсчёта метрик, убирает
~200 строк и один класс дефектов.

### 7. Опечатки в публичном API

`GroupDevidedMetricsWrapper`, параметр `columns_to_devide`, файл `avatar/metrics/utils/group_devided_wrap.py`
(правильно — divided), `epmty` в комментарии `group_average_wrap.py:69`. Переименовать
с шимом на один релиз — ровно тем же приёмом, каким только что убрали шимы в
`avatar/nn`. Класс используется только в двух yaml внутри `docs/`, так что цена
переименования сейчас минимальна; через полгода она будет выше.

### 8. Тесты

Это главный пункт, без него остальные не удержатся. Минимум:

* **контрактные тесты, параметризованные по всем классам модуля**: `compute()` дважды
  подряд даёт одно и то же; `reset()` возвращает в исходное состояние; `compute()`
  всегда возвращает `dict`. Эти три теста ловят B1, S2 и S12 разом;
* **золотые значения** против `sklearn` / `sklift` на фиксированном массиве — ловит
  S1, S2, S3, S11;
* **краевые случаи**: срез из одних позитивов, из одних негативов, пустой, одна
  группа, группа появляется на второй эпохе — ловит S4 и S5.

### 9. Мелочи одной строкой

* `zip(..., strict=False)` в `group_devided_wrap.py:56,90,97` и
  `sequence_stats.py:150` — при рассинхроне `columns_to_devide` и `columns_desc`
  конфиг молча даст неправильные имена метрик. Здесь нужен `strict=True`.
* `_build_input_output_by_mask` (`group_devided_wrap.py:66-74`) тихо теряет ключи
  входа, которые не `dict` / `list` / `Tensor` — например numpy-массивы.
* `import os` внутри функций: `uplift.py:353`, `supervised.py:284`, `supervised.py:448`.
* `HiddensNorm.__init__` (`sequence_stats.py:139`) — лишний `pass`;
  `SequenceStats.reset` (`sequence_stats.py:78`) присваивает `self._event_ids`,
  которого больше нигде нет.
* `RocAucScore` считает один и тот же ROC AUC дважды — `roc_auc_score` (строка 82) и
  `roc_auc_score_overall` (строка 124).
